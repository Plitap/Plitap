# Карта PLITAP

Каждый репозиторий отвечает за отдельное направление. Эта карта описывает размещение будущей работы; её техническая реализация ещё проектируется.

## Репозитории

| Репозиторий | Назначение |
|---|---|
| [Plitap](https://github.com/Plitap/Plitap) | Главная страница, карта проекта, общий план и порядок решений. |
| [spec](https://github.com/Plitap/spec) | Общие правила PLITAP: устройство плиток, типы, операции, сетевое взаимодействие и развитие спецификации. |
| [core](https://github.com/Plitap/core) | Проверка форматов плиток, подписей, полномочий и допустимости изменений по спецификации PLITAP. |
| [network](https://github.com/Plitap/network) | Поиск участников и передача данных PLITAP: P2P-соединения, локальные каналы, ретрансляция и возобновление доставки. |
| [node](https://github.com/Plitap/node) | Программа независимого участника PLITAP: распределённое состояние, хранение, синхронизация и восстановление. |
| [sdk](https://github.com/Plitap/sdk) | Библиотеки, интерфейсы и примеры для создания приложений и интеграций на основе PLITAP. |
| [client](https://github.com/Plitap/client) | Универсальное пользовательское приложение PLITAP для работы с цифровыми плитками. |
| [game](https://github.com/Plitap/game) | Придумываем игру или игры и игровые плитки на основе PLITAP. Геопоиск, передачи, коллекционирование и усиление. Открыты предложениям. |
| [conformance](https://github.com/Plitap/conformance) | Тестовые примеры и сценарии для проверки соответствия реализаций спецификации PLITAP. |
| [security](https://github.com/Plitap/security) | Модель угроз, исследования защиты и проверка безопасности компонентов PLITAP. |
| [research](https://github.com/Plitap/research) | Исследования, сравнение архитектурных вариантов и экспериментальные стенды PLITAP. |
| [docs](https://github.com/Plitap/docs) | Понятные руководства, объяснения и материалы для пользователей и разработчиков PLITAP. |

| [design](https://github.com/Plitap/design) | Визуальная система PLITAP: бренд, принципы интерфейса и общие материалы. |
| [.github](https://github.com/Plitap/.github) | Общие правила участия, шаблоны задач и организация работы в репозиториях PLITAP. |

## Где искать конкретную задачу

| Задача | Место |
|---|---|
| Обязательное правило или формат плитки | `spec` |
| Тип плитки, его версия и обсуждение | `spec/types` |
| Проверка формата, подписи и допустимости перехода | `core` |
| Соединения, Bluetooth, Wi-Fi, интернет и спутниковые каналы | `network` |
| Программа независимого узла, хранение и согласование состояния | `node` |
| Пакет для интеграции или пример его использования | `sdk` |
| Пользовательское приложение | `client` |
| Описание игрового направления и предложения | `game` |
| Проверка совместимости разных реализаций | `conformance` |
| Модель угроз и публичный результат проверки защиты | `security` |
| Сравнение вариантов и эксперимент до принятия решения | `research` |
| Руководство для пользователя или разработчика | `docs` |
| Код сайта | `website` |
| Общий бренд и визуальные материалы | `design` |
| Общие инструкции участия и шаблоны GitHub | `.github` |

## Как связаны направления

- `spec` задаёт правила. `core` реализует проверки по этим правилам.
- `network` отвечает за поиск участников и доставку данных. Доставка сама по себе не подтверждает владение.
- `node` использует проверки и обмен для выполнения своей роли независимого участника сети. Хранение копии не даёт дополнительных полномочий.
- `sdk` предоставляет удобные интерфейсы для приложений; общие правила не копируются в независимые версии внутри каждого приложения.
- `conformance` проверяет соответствие конкретной версии `spec`. Совпадение с одним нашим компонентом не является единственным критерием.
- `security` рассматривает защиту всей системы. Исполняемые защитные механизмы находятся рядом с соответствующим кодом.
- `docs` объясняет, как пользоваться опубликованными возможностями. Нормативные определения остаются в `spec`.

Конкретные зависимости пакетов, алгоритмы, языки и платформы определяются при проектировании. Список направлений не закрепляет их заранее.

## Правила размещения

1. У нормативного правила одно основное место — `spec`. Остальные документы ссылаются на нужную версию.
2. Реализация и её внутренние тесты находятся в одном репозитории. Общие проверки нескольких реализаций относятся к `conformance`.
3. Инструкции сборки компонента остаются рядом с кодом; общие руководства — в `docs`.
4. Исследовательское предложение, принятое решение и проверенная реализация обозначаются отдельно.
5. В `game` сейчас размещаются только описание и README. Структура игр и количество проектов не определены.

## Названия и версии

Имена репозиториев короткие, по назначению. Версии отражаются в выпусках и тегах, а не в названиях вроде `new`, `final` или `v2`. Исключения в написании — профильный `Plitap` и служебный `.github`.
